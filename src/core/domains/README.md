# Domain pack handoff

`DomainDefinition` and `DomainResultBinding` are the C05-owned contracts. The validated catalog resolves an active server-configured pack for a new thread; C02 must persist that pack ID/version as the thread's immutable pin. A caller must build `DomainResultPublicationInput` from authoritative server context: `scope`, `threadId`, `agentRunId`, and `toolCallId` must come from the authenticated request and C02 thread/run lifecycle. Never populate these fields from model arguments, forwarded props, or client headers.

C03 owns the `BusinessTool` definition and MCP execution. The read-only C03 handoff currently exposes `calculate_budget` version `1.0.0`, with the model-facing name `business__calculate_budget`. C05 references that exact name/version in the pack and binding; it does not define a second tool executor. C03's decoded, schema-validated tool output is the input to `publishDomainToolResult`. The integration point is after C03 output validation and before C03 resolves the tool result to the model. Publication may fail the business call, but successful publication must return the original tool output unchanged to C03/model. Calls without an output binding pass through without publication.

`publishDomainToolResult` validates the tool output, binding-derived run input, artifact draft/envelope, presenter blocks, and references before calling `DomainResultPublicationPort.publish`. The port candidate contains validated business data and the server-resolved publication key `(workspaceId,userId,threadId,agentRunId,toolCallId,bindingId)`, plus the same resolved correlation in its binding and outbox reference. `tests/contracts/domain-result-publication.test.ts` pins this boundary.

## C02 integration gate

C02 must implement the port as one atomic transaction. In that transaction it persists the completed business run/snapshot, artifact, scoped binding, immutable `ResultView`, and outbox reference/event. It enforces idempotency on the publication key: same key and semantic fingerprint returns the original IDs/publication; same key with changed semantics fails with `domain_result_publication_conflict` and writes nothing. The `domain_result` event carries `publicationId`, `threadId`, `agentRunId`, `toolCallId`, pack ID/version, `businessRunId`, and artifact references; it contains no credentials or unrestricted URLs.

C02 owns thread pin persistence, transcript/history integration, event delivery, replay, and scoped read authorization. This checkout has the C05 contracts and publication builder but no C02 transaction/thread service. The scoped result/artifact routes and history adapter therefore await C02 integration; this documentation and contract test do not claim end-to-end persistence or replay.

Any failure before the atomic commit (validation, presenter, reference checks, storage, idempotency conflict, or transaction failure) is a technical tool-call failure. C03 maps technical failures to the exact user-facing text `Chưa kết nối`; diagnostics remain server-side and safe. A failure to read/render a result after a successful commit does not undo the completed tool call or rerun the business handler.
